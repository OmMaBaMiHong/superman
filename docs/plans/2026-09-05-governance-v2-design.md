## 0. 数据底座声明（用户关切澄清）

**主库就是 PostgreSQL，从未用过 SQLite。** 数据资产化路线：

- **全量沉淀**：原始载荷（payload_json）、治理后字段、热榜快照、作品表现快照——全部只追加不覆盖，历史即资产
- **语义层**：pgvector 已装（迁移 0041，knowledge_embeddings 表）——知识库问答（"问我自己的知识库"式 RAG）随时可做
- **分析层**：热榜与作品表现都是时间序列，趋势分析/大盘预测有数据基础
- **Obsidian 式用法**：Markdown 导出 + 本地知识库目录同步（后续批次）
- **图数据库**：暂不上。等做"博主-话题-事件"关系图谱时再评 Neo4j——PG 的递归查询和 pgvector 目前够用

## 1. 数据治理 v2：从"审进来"到"洗干净、分对路、为我所用"

### 现状（v1）
抓取 → URL/标题去重 → AI 拟折打分 → 配额 → 待批。只回答"收不收"，不回答"对我有什么用"。

### v2 管线（六站）

```
采集 → ①归一化 → ②去重合并 → ③方向分类（策略模板） → ④AI 拟折 → ⑤方向配额 → ⑥待批
```

**① 归一化**（学 hotspot-tracking-system）：标题 Unicode NFKC 归一、去空白/表情符号差异、URL 去追踪参数（utm_* 等）。bigram 去重前先做这步，命中率翻倍。

**② 去重合并**（修 hotspot 的教训）：
- Postgres 唯一约束 + ON CONFLICT 兜底（他们没加唯一约束，并发会双写）
- 三级：URL 精确 → 归一化标题精确（跨平台合并：同一事件多平台热搜合并成一条多平台记录）→ bigram ≥0.78 模糊
- 驳回记忆保留（7 天）

**③ 方向分类：策略模板化（核心设计，用户拍板）**

**方向不是写死的枚举——每个方向 = 一条策略模板，后续新增方向零代码。**

新表 `direction_strategies`（迁移 0055）：

| 字段 | 说明 |
|---|---|
| key | 唯一标识（topic/money/learning/general 内置四个） |
| name / color / icon | UI 展示：徽章、筛选器、统计全部按模板表动态渲染 |
| keywords_dsl | 关键词规则（TrendRadar DSL 简版：`+必须` `-排除` `/正则/`），命中即归类 |
| ai_hint | 给 AI 分类器的自然语言定义（"什么算这个方向"）；拟折 prompt 动态拼装全部启用模板 |
| quota_weight | 方向配额权重（见 ⑤） |
| enabled / sort | 启停与排序 |
| builtin | 内置标记：可改规则和权重、不可删；用户自建模板可删 |

初始四个模板（用户原话定义）：

| key | 名称 | 定义 | 例子 |
|---|---|---|---|
| topic | 选题 | 今天我想口播/二创的素材 | 热点事件、爆款视频、热议话题 |
| money | 搞钱 | 别人的文稿/热点里的商机灵感 | 变现案例、新平台红利、工具差价 |
| learning | 学习 | 真干货，值得收藏 | 深度教程、方法论、行业分析 |
| general | 其他 | 兜底（不可删，权重可为 0） | — |

分类双通道：
- **关键词派（零成本先做）**：按模板的 keywords_dsl 逐条匹配，先匹配先归类（sort 即优先级）
- **AI 派（增强）**：关键词未命中时，拟折 prompt 带上所有启用模板的 name+ai_hint，LLM 输出 direction_key + 置信度

设置页加「方向策略」面板（CRUD + 启停 + 权重滑杆），改动实时生效——**加方向 = 加一行模板，不动代码**。

**④ AI 拟折**：保留质量分 0-100，新增 direction_key + direction_reason（"这事为什么能搞钱"一句话）。

**⑤ 方向配额**：每日配额按启用模板的 quota_weight 归一化分配，保证待批队列各方向均衡供给，不被娱乐新闻淹没。

**⑥ 待批**：审批卡片显示方向徽章（颜色取模板 color），审批台按方向筛选（选项从模板表动态来）。

### 数据形态变更
- articles 加列：`direction_key` text、`direction_reason` text（迁移 0055，与 direction_strategies 同迁移）
- trend_radar_items 合并入治理时走同一管线
- 治理动作带算法版本（分类规则与权重版本记入 payload，可回放复盘——学 hotspot 的 Run/Entry 模型）

## 2. 创作台 v2：补上"发布后"这半条命

现状只有"产前"（审批/选题/任务/草稿）。完整闭环：

```
选题 → 二创（洗稿）→ 发布（授权中心）→ 发布后表现追踪 → 表现反哺选题
```

**新增「表现」区（创作台第五 tab）**：
- 新表 `published_posts`（id, user_id, draft_id, platform, account_id, post_url, title, published_at）——发布登记（手动填链接先行，授权中心接通后自动登记）
- 新表 `post_metrics_snapshots`（post_id, fetched_at, views, likes, comments, shares, followers_delta, raw_json）——快照只追加；插件 worker 定时抓（发布后 72h 每小时，之后每天）
- 表现页：作品数据曲线（7 天）、热力标记（涨幅超阈值 🔥）、**「火了快出续集」提示**——表现超线自动把原选题 requeue 回审批台 + 写消息中心
- 评论抓取（二期）：作品评论 → 关键词/情感粗分析 → 反哺选题池（"观众都在问 X"自动生成选题候选）
