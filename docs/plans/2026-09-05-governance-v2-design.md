# 数据治理 v2 · 创作台深化 · 消息中心 —— 设计文档

> 日期：2026-09-05 · 状态：定稿待实施 · 关联：总计划、DSH 内核拓扑
> 输入：用户三方向诉求（选题/搞钱/学习）+ 五份对标深度报告（reports/deep-dive-*.md）

---

## 1. 数据治理 v2：从"审进来"到"洗干净、分对路、为我所用"

### 现状（v1）
抓取 → URL/标题去重 → AI 拟折打分 → 配额 → 待批。只回答"收不收"，不回答"**对我有什么用**"。

### v2 管线（六站）

```
采集 → ①归一化 → ②去重合并 → ③方向分类 → ④AI 拟折 → ⑤方向配额 → ⑥待批
```

**① 归一化**（学 hotspot-tracking-system `utils.ts`）：标题 Unicode NFKC 归一、去空白/表情符号差异、URL 去追踪参数（utm_* 等）。v1 的 bigram 去重前先做这步，命中率翻倍。

**② 去重合并**（修 hotspot 的教训）：
- Postgres 唯一约束 + ON CONFLICT 兜底（他们没加唯一约束，并发会双写）
- 三级：URL 精确 → 归一化标题精确（跨平台合并：同一件事微博/知乎/百度都上热搜时合并成一条多平台记录，而不是三条候选）→ bigram ≥0.78 模糊
- 驳回记忆保留（7 天）

**③ 方向分类（核心新增）**：每条内容进待批前打一个方向标签：

| 方向 | 定义（用户原话） | 例子 |
|---|---|---|
| `topic` 选题 | 今天我想口播/二创的素材 | 热点事件、爆款视频、热议话题 |
| `money` 搞钱 | 别人的文稿/热点里的商机灵感 | 变现案例、新平台红利、工具差价 |
| `learning` 学习 | 真干货，值得收藏的 | 深度教程、方法论、行业分析 |
| `general` 其他 | 以上都不是 | — |

实现双通道（学 TrendRadar 的两派）：
- **关键词派（零成本先做）**：core 里实现 TrendRadar 关键词 DSL 的简版（`+必须 -排除 /正则/ [组别名]`），三个方向各一组关键词，命中即归类，组别名即方向名
- **AI 派（增强）**：拟折 prompt 增加 direction 字段输出（四选一 + 置信度），关键词没命中时由 AI 定；prompt 里给三个方向的自然语言定义（学 TrendRadar ai_interests.txt 的"优先级自然语言"写法）

**④ AI 拟折**：保留质量分 0-100，新增 `direction` + `direction_reason`（"这事为什么能搞钱"一句话）。

**⑤ 方向配额**（升级三省六部配额制）：governance_preferences 加 `direction_weights`（默认 topic 40% / money 30% / learning 30%），每类每日配额按方向权重再分配——保证你的待批队列每天都有三方向的均衡供给，不被娱乐新闻淹没。

**⑥ 待批**：审批卡片上显示方向徽章（选题=绿/搞钱=琥珀/学习=紫），审批台支持按方向筛选。

### 数据形态变更
- articles 加列：`direction` text、`direction_reason` text（迁移 0054）
- trend_radar_items 合并入治理时走同一管线
- 治理动作日志保留（学 hotspot 的 Run/Entry 带算法版本：分类规则和权重版本号记入 payload，可回放）

## 2. 创作台 v2：补上"发布后"这半条命

现状只有"产前"（审批/选题/任务/草稿）。用户要的完整闭环：

```
选题 → 二创（洗稿）→ 发布（P2 授权中心）→ 发布后表现追踪 → 表现反哺选题
```

**新增「表现」区（创作台第五 tab）**：
- 新表 `published_posts`（id, user_id, draft_id, platform, account_id, post_url, title, published_at）——发布时登记（手动填链接先行，P2 授权中心接通后自动登记）
- 新表 `post_metrics_snapshots`（post_id, fetched_at, views, likes, comments, shares, followers_delta, raw_json）——**快照只追加**（hotspot 的快照模型），插件 worker 定时抓（频率：发布后 72h 每小时，之后每天）
- 表现页：每个作品的数据曲线（7 天）、热力标记（涨幅超阈值标🔥）、**「火了快出续集」提示**——表现超线自动把原选题 requeue 回审批台 + 写消息中心
- 评论抓取（二期）：抓作品评论 → 关键词/情感粗分析 → 反哺选题池（"观众都在问 X"自动生成新选题候选）

## 3. 消息中心（底部菜单第五 tab）

- 新表 `notifications`（id, user_id, kind, title, body, link, read_at, created_at）
- 事件源：采集失败 / 待批积压（>10 条提醒）/ 流水线完成 / 重拟完成 / **作品表现异动**（§2）/ 授权过期（P2）
- 底部 tab：阅读 / 创作 / 热点 / **消息（未读徽章）** / 设置
- 消息页：按天分组、点击跳对应页面、全部已读；30s 轮询未读数
- 预留 Web Push（PWA）

## 4. 实施批次

| 批次 | 内容 | 依赖 |
|---|---|---|
| **P2a** | 消息中心（表+事件+tab+页） | 无 |
| **P2b** | 治理 v2：归一化 + 跨平台合并 + 唯一约束 + 关键词方向分类 + 方向徽章/筛选 | P2a 的事件挂钩 |
| **P2c** | AI 方向分类 + 方向配额 + 审批台按方向筛 | P2b |
| **P2d** | 发布后表现追踪（表+快照抓取+表现 tab+火了提示） | 手动登记先行，自动登记等授权中心 |
| **P2e** | 平台授权中心（公众号→抖音→小红书，按调研报告顺序） | 独立 |

每个批次独立可交付、可验收，不阻塞主线。
