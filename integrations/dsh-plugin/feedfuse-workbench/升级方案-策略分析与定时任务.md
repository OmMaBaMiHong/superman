## 二、存储层：PostgreSQL + pgvector

### 2.1 依赖变更

`package.json` 新增：
```json
{
  "dependencies": {
    "pg": "^8.13.0",
    "pgvector": "^0.2.0"
  }
}
```

连接配置：通过 `DATABASE_URL` 环境变量（对齐原 FeedFuse），格式：
```
postgresql://user:pass@host:5432/feedfuse
```

### 2.2 数据库表设计

#### 复用原 FeedFuse 核心表（对齐 schema）

```sql
-- 订阅分类
CREATE TABLE categories (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL,
  position INT NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 订阅源
CREATE TABLE feeds (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title TEXT NOT NULL,
  url TEXT NOT NULL,
  site_url TEXT,
  icon_url TEXT,
  platform TEXT,          -- 'douyin' | 'bilibili' | 'youtube' | NULL
  enabled BOOLEAN NOT NULL DEFAULT TRUE,
  category_id BIGINT REFERENCES categories(id) ON DELETE SET NULL,
  fetch_interval_minutes INT NOT NULL DEFAULT 30,
  last_fetched_at TIMESTAMPTZ,
  last_fetch_status INT,
  last_fetch_error TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE UNIQUE INDEX feeds_url_unique ON feeds(url);

-- 文章/视频条目
CREATE TABLE articles (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  feed_id BIGINT NOT NULL REFERENCES feeds(id) ON DELETE CASCADE,
  dedupe_key TEXT NOT NULL,           -- guid 或 awemeId
  title TEXT NOT NULL,
  link TEXT,
  author TEXT,
  published_at TIMESTAMPTZ,
  content_html TEXT,
  summary TEXT,
  media_type TEXT NOT NULL DEFAULT 'article',  -- 'video' | 'article'
  video_url TEXT,
  duration_sec INT DEFAULT 0,
  stats JSONB,                        -- {likes, comments, shares, collects, plays}
  fetched_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  is_read BOOLEAN NOT NULL DEFAULT FALSE,
  -- 文案提取
  transcript TEXT,
  transcript_source TEXT,             -- 'subtitle' | 'whisper'
  transcript_extracted_at TIMESTAMPTZ,
  -- AI 分析状态
  last_analyzed_at TIMESTAMPTZ,
  analysis_count INT DEFAULT 0
);
CREATE UNIQUE INDEX articles_dedupe_unique ON articles(feed_id, dedupe_key);
CREATE INDEX articles_feed_published_idx ON articles(feed_id, published_at DESC);
CREATE INDEX articles_media_type_idx ON articles(media_type);
```

#### 新增：策略模板表

```sql
CREATE TABLE strategy_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,                   -- 策略名称（如"变现逻辑分析"）
  slug TEXT NOT NULL UNIQUE,            -- 唯一标识（如 'monetization'）
  description TEXT,
  -- 策略提示词
  system_prompt TEXT NOT NULL,          -- 系统提示词
  user_prompt_template TEXT NOT NULL,   -- 用户提示词模板（支持 {{title}} {{transcript}} 等变量）
  -- 输出 schema（JSON Schema 格式，用于校验 Agent 输出）
  output_schema JSONB NOT NULL,
  -- 模型配置
  model_provider TEXT,
  model_name TEXT,
  max_tokens INT DEFAULT 2048,
  -- 元数据
  is_builtin BOOLEAN NOT NULL DEFAULT FALSE,  -- 内置策略不可删除
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

#### 新增：分析结果表

```sql
CREATE TABLE analysis_results (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  article_id BIGINT NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  strategy_id UUID NOT NULL REFERENCES strategy_templates(id) ON DELETE CASCADE,
  -- 分析输出（结构化 JSON）
  result JSONB NOT NULL,
  -- 关键字段冗余存储（便于查询和聚合）
  category TEXT,                        -- 一级分类
  tags TEXT[],                          -- 标签数组
  score INT,                            -- 综合评分 0-100
  priority INT,                         -- 优先级 1-5
  sentiment TEXT,                       -- 'positive' | 'neutral' | 'negative'
  -- 模型与耗时
  model_provider TEXT,
  model_name TEXT,
  tokens_used INT,
  duration_ms INT,
  -- 元数据
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX analysis_results_article_idx ON analysis_results(article_id);
CREATE INDEX analysis_results_strategy_idx ON analysis_results(strategy_id);
CREATE INDEX analysis_results_category_idx ON analysis_results(category);
CREATE INDEX analysis_results_score_idx ON analysis_results(score DESC);
CREATE INDEX analysis_results_tags_gin ON analysis_results USING GIN(tags);
CREATE INDEX analysis_results_result_gin ON analysis_results USING GIN(result);
```

#### 新增：知识库向量表（pgvector）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE knowledge_embeddings (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  article_id BIGINT NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  strategy_id UUID REFERENCES strategy_templates(id) ON DELETE SET NULL,
  chunk_index INT NOT NULL,
  chunk_text TEXT NOT NULL,
  chunk_type TEXT NOT NULL DEFAULT 'transcript',  -- 'transcript' | 'analysis' | 'summary'
  embedding vector(1536),               -- OpenAI embedding 维度
  metadata JSONB,                       -- 额外元信息

CREATE INDEX knowledge_embeddings_article_idx ON knowledge_embeddings(article_id);
CREATE INDEX knowledge_embeddings_embedding_idx ON knowledge_embeddings
```

#### 新增：调度器日志表

```sql
CREATE TABLE scheduler_runs (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

  total_count INT DEFAULT 0,
  succeeded_count INT DEFAULT 0,
```

### 2.3 SQLite → PostgreSQL 迁移策略

首次启动时检测：
1. 如果 `DATABASE_URL` 已配置且 PostgreSQL 连接成功 → 走 PG
2. 如果 PG 不可用 → 回退到现有 SQLite（保持兼容）
3. 迁移：读取 SQLite 全量数据 → 批量写入 PostgreSQL → 标记迁移完成

## 三、策略模板引擎（strategies.js）

### 3.1 策略注册机制

策略模板存储在 `strategy_templates` 表，支持：
- **内置策略**：插件启动时自动注册（is_builtin=true）
- **用户自定义策略**：通过 API 创建/编辑/删除

### 3.4 策略执行流程

```
1. 加载策略模板（从 DB）
2. 构建 prompt（替换变量：{{title}} {{transcript}} {{author}} {{stats}}）
3. 调用 LLM（走 ctx.llm.stream）
4. 解析 JSON 输出
5. 校验 output_schema
6. 写入 analysis_results 表
7. 更新 articles 的 last_analyzed_at / analysis_count
8. 提取 tags 写入 article_tags
9. 生成 embedding 写入 knowledge_embeddings
```

## 四、定时任务引擎（scheduler.js）

### 4.1 任务类型

| 任务 | 默认频率 | 说明 |
|------|----------|------|
| fetch | 每天 08:00 | 抓取所有订阅源新视频 |
| transcribe | 每天 09:00 | 提取未解析视频的文案 |
| analyze | 每天 10:00 | 对所有未分析视频执行策略分析 |
| embed | 每天 11:00 | 对新分析结果生成向量嵌入 |

### 4.2 实现方式

使用 `node-cron` 或自研简单调度器（setInterval + cron 表达式解析），避免额外依赖。

核心逻辑：
```js
// scheduler.js 核心结构
export function createScheduler({ config, rss, strategies, knowledge }) {
  const jobs = new Map()  // name -> { cron, task, lastRun, running }

  // 注册内置任务
  registerJob('fetch', '0 8 * * *', () => rss.refreshAll())
  registerJob('transcribe', '0 9 * * *', () => transcribePending())
  registerJob('analyze', '0 10 * * *', () => analyzePending())
  registerJob('embed', '0 11 * * *', () => embedPending())

  return {
    start(), stop(), status(),
    runJob(name),  // 手动触发
    listJobs(),
  }
}
```

### 4.3 任务链与依赖

```
fetch → transcribe → analyze → embed
  ↓         ↓          ↓         ↓
  └─────────┴──────────┴─────────┘
             全部记录到 scheduler_runs
```

每个任务执行前检查依赖：
- transcribe 只处理有 video_url 且无 transcript 的
- analyze 只处理有 transcript 且未分析（或分析过期）的
- embed 只处理有新分析结果且无 embedding 的

## 五、知识库存储（knowledge-store.js）

### 5.1 职责

- PostgreSQL 连接管理（连接池）
- 所有表的 CRUD 封装
- 向量嵌入的存储与相似度查询
- 全文检索查询
- 聚合查询（按分类/标签/评分/时间）

### 5.2 核心 API

```js
export function createKnowledgeStore({ connectionString }) {
  return {
    // 初始化
    async init(),           // 建表 + 迁移 + 注册内置策略
    async health(),         // 连接健康检查

    // 订阅源
    listFeeds(), getFeed(id), addFeed(input), deleteFeed(id),

    // 文章
    listArticles(filter), getArticle(id), updateArticle(id, patch),
    ingestArticles(feedId, items),  // 抓取后批量写入

    // 策略
    listStrategies(), getStrategy(slug), createStrategy(input), deleteStrategy(id),

    // 分析
    analyzeArticle(articleId, strategySlug),
    listAnalysisResults(filter),

    // 知识库（向量 + 全文）
    semanticSearch(query, limit),       // pgvector 相似度搜索
    fullTextSearch(query, limit),      // GIN 全文索引
    hybridSearch(query, limit),        // 向量 + 全文混合

    // 聚合
    getCategories(),                    // 分类聚合
    getTags(),                          // 标签云
    getTrending(period),                // 趋势
    getMonetizationStats(),             // 变现分析统计

    // 看板
    listBoards(), createBoard(), addToBoard(),

    // 调度
    logSchedulerRun(data), getSchedulerRuns(),
  }
}
```

### 5.3 向量嵌入生成

调用 LLM 的 embedding API（如 OpenAI `text-embedding-3-small`）生成 1536 维向量：
- 对 transcript 分段（每段 ~500 字）
- 对 analysis result 的 summary 字段
- 存储到 knowledge_embeddings 表

## 六、HTTP API 端点

### 6.1 调度器控制

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /feedfuse/scheduler/status | 调度器状态 + 任务列表 |

| POST | /feedfuse/scheduler/stop | 停止调度器 |
| POST | /feedfuse/scheduler/run | 手动触发任务 `{ job: 'fetch' }` |

### 6.2 策略管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /feedfuse/strategies | 策略列表 |

| PUT | /feedfuse/strategies/:id | 更新策略 |

| 方法 | 路径 | 说明 |
|------|------|------|

### 6.4 分析

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /feedfuse/analyze | 执行分析 `{ articleId?, strategySlug?, all? }` |
